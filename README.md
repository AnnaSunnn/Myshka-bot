# Бот порад для звірів (Telegram)

Звірі надсилають боту документи (PDF, DOCX, TXT) з порадами, інші питають, бот відповідає й завжди називає джерело: документ, ім'я автора, дату надходження.

## Запуск

**Потрібно:** Docker з Docker Compose, токен Telegram-бота (@BotFather) і безкоштовний ключ Groq (console.groq.com → API Keys). Токени передаються лише через змінні оточення й не зберігаються в репозиторії, файл `.env` у git не потрапляє.

```bash
cp .env.example .env     # впишіть TELEGRAM_BOT_TOKEN і GROQ_API_KEY
docker compose up --build
```

Змінні також можна передати з оболонки (`export TELEGRAM_BOT_TOKEN=... GROQ_API_KEY=...`). База SQLite лежить у docker-volume `bot_data`. LLM: Groq, модель `openai/gpt-oss-120b`; якщо вона недоступна, вкажіть іншу в `GROQ_MODEL` (наприклад, `llama-3.3-70b-versatile`).

Корисні команди:

```bash
docker compose logs -f bot    # логи
docker compose down -v        # зупинити й скинути базу
```

## Команди бота

- `/start`, `/help` — підказка;
- `/my` — ваші документи з кнопкою видалення.

## Правила (узгоджені з замовницею)

- Один документ = один рівень: весь ліс, одна частина лісу або одна рукавичка. Якщо з тексту незрозуміло або рівнів кілька, бот перепитує автора кнопками й не вгадує.
- Структура місць і частин лісу: `bot/config.py`.
- Перше завантаження: бот питає справжнє ім'я й запам'ятовує.
- Підтвердження: перед збереженням бот показує назву документа й визначений рівень, документ зберігається лише після кнопки «Так».
- Оновлення: якщо для цього рівня (рукавички, частини лісу або всього лісу) вже є актуальні документи, бот питає «нова версія чи окрема порада». Оновити може будь-хто. Замінена версія більше ніколи не показується (в базі лишається неактивною), а якщо нову версію надіслав інший звір, попереднього автора сповіщають.
- Запитання мають називати місце, частину лісу або весь ліс; без цього бот перепитує.
- Пріоритет: рукавичка, потім частина лісу, потім весь ліс. Порядок рівнів задає код, а чи є відповідь на рівні, вирішує LLM: береться найспецифічніший рівень, де є відповідь. Для «Під вербою» на одному рівні діють і «листяний», і «біля річки». Якщо на рівні діє кілька окремих документів із відповіддю, бот показує їх усі, кожен зі своїм джерелом: найновіший першим, решта під заголовком «Також на цьому рівні (інші документи)». Загальнішу пораду бот додає окремо.
- Немає відповіді: бот чесно каже про це, без власних знань.
- Відповідь: переказ + дослівний уривок (перевіряється, що він справді є в документі) + джерело.
- Файл не читається: помилка й прохання надіслати інший, нічого не зберігається.
- Дубль (за хешем тексту в межах того самого рівня): бот повідомляє, що документ уже є. Той самий текст для іншого місця можна додати.
- Видалення: `/my`, лише автор. Документ позначається як видалений і більше не показується, запис лишається в базі.
- Спілкування лише в особистих повідомленнях; у групових чатах бот мовчить.
- Дата надходження показується за київським часом.

## Рішення, ухвалені самостійно

Замовниця делегувала ці питання, про рішення їй повідомлено:

- Бот відповідає лише з документів, без власних знань.
- Після уточнення місця бот просить підтвердження кнопкою перед збереженням.
- До відповіді додається дослівний уривок, який перевіряється кодом.
- Файл, що не читається, не зберігається.
- Видалити документ може лише автор.
- Оновити документ може будь-хто.
- Точний дубль у межах того самого рівня не додається.
- Питати можна й про частину лісу чи весь ліс, а не лише про рукавичку.

## Структура проєкту

- `bot/main.py` — обробники Telegram і логіка діалогу;
- `bot/llm.py` — виклики Groq (визначення рівня, місця, відповіді);
- `bot/retrieval.py` — нарізка документів і відбір фрагментів;
- `bot/db.py` — SQLite;
- `bot/extract.py` — текст із PDF, DOCX, TXT;
- `bot/config.py` — налаштування, місця й частини лісу.

## Обмеження

- Приймаються PDF, DOCX і TXT до 20 МБ; скани й фото не підтримуються.
- Документи нарізаються на фрагменти (~900 символів), у LLM іде до 6000 символів найрелевантніших до запитання фрагментів на рівень. Довгі документи не обрізаються.
- Відбір фрагментів працює за збігом слів, а не за змістом, тому запитання й документ, написані різними словами, можуть не збігтися.
- Запит до Groq при ліміті 429 повторюється (до 3 спроб).
- Стан діалогу (FSM) тримається в пам'яті: після перезапуску незавершене завантаження треба повторити.
- Бот розрахований на один запущений екземпляр (polling і SQLite).
